# Output layout after refactor

The project no longer creates one `results/<model_name>[_crf]/` tree per model.
All artifact-type directories are shared. The model name and CRF flag are encoded in every filename.

```text
results/
├── checkpoints/
│   ├── bilstm_latest_model.pt
│   ├── bilstm_best_model.pt
│   ├── phobert_crf_latest_model.pt
│   └── phobert_crf_best_model.pt
├── logs/
│   ├── main_orchestrator_2026-10-16_16-00-00.log
│   └── phobert_crf_True_2026-10-16_16-00-00.log
├── metrics/
│   ├── bilstm_token_metrics.csv
│   └── phobert_crf_token_metrics.csv
├── plots/
│   ├── bilstm_loss_curve.png
│   ├── bilstm_acc_curve.png
│   ├── bilstm_confusion_matrix.png
│   ├── bilstm_entity_distribution.png
│   └── phobert_crf_loss_curve.png
├── predictions/
│   └── phobert_crf_predictions.txt
└── tensorboard/
    ├── bilstm/
    └── phobert_crf_True/
```

The actual prefix is generated by `model_prefix(model_name, use_crf)`, so `phobert` with CRF becomes `phobert_crf`.

## Hugging Face checkpoint layout

The default private Hugging Face model repository is [`ducbao210/NER`](https://huggingface.co/ducbao210/NER).
You can override it with `HF_CHECKPOINT_REPO_ID` in `.env` or with `--hf_repo_id`.

The remote repository uses the same filename identity as local storage, with one explicit
transport directory named `checkpoints/`:

```text
ducbao210/NER/
└── checkpoints/
    ├── manifest.json
    ├── phobert_crf_best_model.pt
    └── phobert_crf_latest_model.pt
```

The important local destination is always: `results/checkpoints/`. Therefore, after download,
the files are exactly:

```text
results/checkpoints/phobert_crf_best_model.pt
results/checkpoints/phobert_crf_latest_model.pt
```

The program never leaves the downloaded file in the Hugging Face cache as the runtime path.
It copies the selected file into `results/checkpoints/<same_filename>`.

Both checkpoints are required for upload. If either best or latest is missing, upload stops
with an error instead of silently uploading only one file.

During inference the logic is:

1. Look for the explicit `--checkpoint` file if one was provided.
2. Otherwise look for `results/checkpoints/<prefix>_best_model.pt`.
3. If best is absent, look for `results/checkpoints/<prefix>_latest_model.pt`.
4. Only if the required local file is absent, use the read token from `.env` to download
   `checkpoints/<prefix>_best_model.pt` from Hugging Face into `results/checkpoints/`.
5. If remote best is absent, fall back to remote latest.

Configure the token and repository once in the project `.env`:

```dotenv
HF_TOKEN=hf_your_read_write_token_here
HF_CHECKPOINT_REPO_ID=ducbao210/NER
```

Then inference does not need either Hugging Face flag:

```bash
python main.py \
  --model phobert \
  --mode infer \
  --use_crf \
  --infer_text "Bệnh nhân sốt và ho"
```

Upload both files after training:

```bash
python main.py \
  --model phobert \
  --mode train \
  --use_crf \
  --upload_checkpoint
```

The private repository requires an HF token with read permission for inference/download
and write permission for upload.
